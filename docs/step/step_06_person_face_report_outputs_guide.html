EgoCom Person Mapping Outputs Guide

This page is the short index for the person-face mapping artifacts. Use it to decide which JSON or HTML file to open without reading every generated report.

Main result for dataset construction: read {split}/person_face_mapping/{scene_key}/remap_all_chunks.json. It contains the final segment chains: each real person id points to the primary segment id and any additional merged segment ids for every chunk.

Output Flow

Operational mapping files are the JSON files under each scene directory. HTML reports are for inspection and debugging.

What To Open

Build segmentation chains

Open remap_all_chunks.json inside each scene mapping directory.

Check merge cases

Open each split's merged_segments_report.html. It lists only folders where a person has more than one segment id.

Debug conflicts

Open report.html at the split or scene level. It explains selected chunks, fallback chunks, conflicts, and similarity scores.

Split-Level Reports

Path PatternMeaningWhen To Use
{split}/person_face_mapping/report.html Split-wide selected-chunk mapping report. Shows which scenes resolved cleanly and why fallback chunks were used. Use after running src/step_05_map_person_face_embedding.py.
{split}/person_face_mapping/report.json JSON form of the same selected-chunk status. Use for scripts or filtering scenes.
{split}/person_face_mapping/merged_segments_report.html Only lists remap visualization folders that contain merged segment indications. Header shows merged folders / total folders. Use to inspect disconnected tracks that were assigned to the same real person.
{split}/person_face_mapping/merged_segments_report.json Machine-readable rows from the merged segment report. Use to count or batch-open merge cases.
{split}/person_face_mapping/remap_all_chunks_summary.json Per-split aggregate from the all-chunk remap run. Use for split-level validation.

Scene-Level Files

Path PatternMeaningUse For Dataset Construction?
{split}/person_face_mapping/{scene_key}/mapping.json Compact mapping from the selected conflict-free chunk. It establishes the scene's real person labels and representative embeddings. Usually no. It is the seed mapping, not every chunk.
{split}/person_face_mapping/{scene_key}/details.json Detailed selected-chunk diagnostics, including chunk attempts, conflicts, and similarity scores where available. No. Debugging only.
{split}/person_face_mapping/{scene_key}/summary.json Small selected-chunk summary for the scene. No. Status only.
{split}/person_face_mapping/{scene_key}/representative_embeddings.pt Representative face embedding tensors selected from the stable chunk. Indirectly. These are used by remapping, but the chain result is in remap_all_chunks.json.
{split}/person_face_mapping/{scene_key}/representative_crops/ Face/person crop images for visually checking the real person labels. No. Visualization only.
{split}/person_face_mapping/{scene_key}/remap_all_chunks.json Final compact mapping for all chunks. Contains chunks, people, primary_segment_id, and merged_segment_ids. Yes. This is the main chain file.
{split}/person_face_mapping/{scene_key}/remap_all_chunks_details.json Full remap scores, candidate decisions, overlap checks, and rejected merge candidates. No. Debugging only.
{split}/person_face_mapping/{scene_key}/remap_representative_embeddings.pt Representative embeddings for the remapped segment ids. Optional, if you need embedding tensors for follow-up checks.
{split}/person_face_mapping/{scene_key}/remap_visualizations/{clip}/ Representative crop images per mapped person and segment id in each clip. No. Visualization only.
{split}/person_face_mapping/{scene_key}/report.html Scene-level selected-chunk report. It explains conflict reasons and fallback attempts for that scene. No. Debugging only.
