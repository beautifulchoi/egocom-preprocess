Depth-Based Mask Refinement

This page explains how /home/prj/egocom_preprocess/src/step_03_filter_mask.py filters SAM person masks using Depth Anything 3 depth maps. The important detail is that filtering is done per frame and per segment id, not by deleting an id track everywhere.

Goal

SAM sometimes produces a person segment even when there is no real depth boundary between the segment and the surrounding pixels. The script removes those weak segments from a copied mask file while keeping the original person_mask files unchanged.

The output mask is saved at: 

/home/prj/data/egocom_holdout/1min/{split}/refined_mask/{video_name}/mask.pt

Rejected examples are visualized in: 

/home/prj/data/egocom_holdout/1min/{split}/refined_mask/{video_name}/vis/

Data Flow

1. Load masks Reads person_mask/{video}/masks.pt. The format is {frame_idx: {segment_id: bool_mask}}.
2. Load depth Reads each matching DA3 depth map from da3/monocular/{video}/depth/{frame}.npy.
3. Score each instance For each (frame_idx, segment_id), compares mask depth to nearby outer depth.
4. Save copy Removes only rejected frame-level instances, then writes the copied refined mask.

Pipeline Diagram

The decision box is intentionally frame-level. The same segment id can be kept in one frame and rejected in another. A whole id disappears only when every frame instance for that id is rejected.

Frame-Level Rejection

The script does not remove a whole segment id track just because that id has weak depth continuity in some frames. It removes only the exact pair: 

(frame_idx, segment_id)

Example: if id 0 fails in frame 64 but passes in frame 65, frame 64 loses id 0, and frame 65 keeps id 0.

If an id disappears completely in the refined mask, that means every frame instance for that id was rejected. It is a result of frame-level filtering, not a global id deletion rule.

How The Depth Test Works

The first version used only one simple value: the median depth inside the mask versus the median depth in a dilated outer ring. That can be too fragile. For example, a seated person and a couch can have similar depth at the contact area, even though the person still has real depth edges around the head, shoulders, or side boundary.

The current version uses a more robust score with two sources of evidence.

1. Median mask-to-ring contrast

The script still computes the basic median contrast: 

abs(median(mask_depth) - median(outer_ring_depth)) / median(outer_ring_depth)

This is useful when the whole segment is clearly in front of or behind the surrounding area.

2. Robust outer-boundary contrast

The script also checks whether enough pixels in the outer ring are different from the mask interior. This helps when only part of the boundary has a depth edge.

  1. Compute the median depth inside the mask.
  2. For each valid outer-ring pixel, compute its relative difference from the inside median.
  3. Count what fraction of outer-ring pixels pass --local_edge_thresh.
  4. If that fraction is at least --min_edge_fraction, use a high percentile of those differences as boundary evidence.

The final score is: 

max(median_mask_to_ring_contrast, robust_outer_boundary_contrast)

A frame-level segment is rejected only when this final score is below --depth_diff_thresh.

Exact Filtering Algorithm

  1. Collect every video that has both {split}/person_mask/{video}/masks.pt and {split}/da3/monocular/{video}/depth/.
  2. For each frame, load the RGB frame path, the saved SAM masks for that frame, and the matching DA3 depth map named with the same frame stem.
  3. For each segment id in that frame, resize the boolean mask to the depth-map resolution with nearest-neighbor interpolation. This keeps mask labels crisp.
  4. Dilate the resized mask by --dilate_radius. The outer comparison region is dilated_mask AND NOT original_mask.
  5. Skip scoring when either the inside mask or outer ring has fewer than --min_mask_pixels or --min_ring_pixels valid depth pixels. Skipped cases are not rejected because there is not enough evidence.
  6. Compute two discontinuity signals: median_relative_depth_diff and outer_tail_relative_depth_diff. The second signal is trusted only if at least --min_edge_fraction of the outer-ring pixels exceed --local_edge_thresh.
  7. Use depth_discontinuity_score = max(median_relative_depth_diff, robust_boundary_score). This keeps masks when any meaningful part of the boundary has a depth edge.
  8. Reject only the current (frame_idx, segment_id) when depth_discontinuity_score < --depth_diff_thresh.
  9. Save a copied refined mask dictionary without rejected frame instances. The original person_mask file is never modified.
  10. Save every rejected frame-instance visualization by default. Each rejected mask gets its own image in vis/.

Decision Pseudocode

for frame_idx, frame in video:
    depth = load_depth(frame)
    for segment_id, mask in masks[frame_idx]:
        inside = resize(mask, depth.shape)
        outer = dilate(inside) - inside

        if not enough_valid_pixels(inside, outer):
            keep(frame_idx, segment_id)
            continue

        global_score = median_depth_difference(inside, outer)
        boundary_score = high_quantile_outer_boundary_difference(inside, outer)
        score = max(global_score, boundary_score)

        if score < depth_diff_thresh:
            reject_only_this_frame_instance(frame_idx, segment_id)
        else:
            keep(frame_idx, segment_id)

Default Parameters

Parameter Default Meaning
--depth_diff_thresh 0.06 Reject if the final depth-discontinuity score is below 6%.
--dilate_radius 5 How far to expand the mask to create the outer ring.
--local_edge_thresh 0.08 Outer-ring pixels must differ by at least 8% to count as local edge evidence.
--min_edge_fraction 0.08 At least 8% of outer-ring pixels must show edge evidence before the boundary tail is trusted.
--boundary_quantile 90 Uses the 90th percentile of outer-ring contrast, so one small noisy pixel does not dominate.
--min_mask_pixels, --min_ring_pixels 25, 25 Skip scoring when the mask or ring is too small to be reliable.
--vis_sample_every 1 Saves every rejected frame-instance visualization by default.

Summary File

Each video gets a summary.json. The most important fields are:

Field Description
original_segments All ids found in the original mask file.
person_frequency Original id-to-frame-count map, matching the existing mask metadata style.
remaining_person_frequency, rejected_person_frequency Simple id-to-count maps for masks kept after refinement and masks removed by refinement.
remaining_segments Ids still present anywhere in the refined mask. This can be an empty list.
fully_removed_segments Ids with zero remaining frame instances after refinement.
segments_with_rejections Ids that had at least one rejected frame instance.
num_rejected_instances Total number of rejected (frame_idx, segment_id) pairs.
per_segment_counts For each id: original frame count, rejected frame count, and remaining frame count.
original_segment_counts, rejected_segment_counts, remaining_segment_counts Direct id-to-count maps, so each segment id's original, removed, and remaining mask-instance counts are easy to read.
rejected_segments Detailed frame-level records with frame index, segment id, score, and component metrics.
Important: rejected_segments is a list of rejected frame instances. It is not a list of globally deleted ids.
