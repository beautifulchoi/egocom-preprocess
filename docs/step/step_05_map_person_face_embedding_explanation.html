EgoCom Face-Embedding Person Mapping

This document explains src/step_05_map_person_face_embedding.py, which maps clip-local refined-mask segment ids to real scene person ids using face embedding similarity. The script tries chunks in order and falls forward when a chunk produces conflicting person assignments, then writes mapping outputs under the dataset split.

Default command: 
python /home/prj/egocom_preprocess/src/step_05_map_person_face_embedding.py --split train --save_vis
Focused smoke-test command: 
python /home/prj/egocom_preprocess/src/step_05_map_person_face_embedding.py --split train --scene_key day_1__con_1__part1 --save_vis --overwrite

Input Layout

The script expects the existing EgoCom preprocessing layout under /home/prj/data/egocom_holdout/1min/{split}. For each candidate chunk, it reads:

Input Purpose
refined_mask/{clip}/summary.json Provides remaining_person_frequency, used to choose the top counted segment masks.
refined_mask/{clip}/mask.pt Frame-indexed masks used for fallback counting and representative crop bboxes.
person_face_emb/{clip}/embeding.pt Per-segment face embeddings, frame indices, frame stems, and detection scores.
frame/{clip}/*.jpg Original frames used to save representative crop visualizations.
Data read by the mapper and the output products it creates.

Scene Grouping

Clip names are parsed with this pattern: vid_*__day_*__con_*__person_*[_partN]_chunk_*. Chunks are grouped by the same scene key and tried in ascending chunk order. Scene keys include the part when present, for example day_1__con_1__part1. If a name has no part, the scene key is day_X__con_Y.

Each pair of camera wearers shares exactly the third person in a normal 3-view scene.

Mapping Algorithm

  1. For each scene, start with the lowest available chunk number and choose at most two segment ids per clip by descending remaining_person_frequency.
  2. Load embeddings only for those selected segment ids. If a top segment has no embedding, it remains recorded as missing and is not backfilled.
  3. Reject any selected segment with fewer than 10 face embeddings; it is recorded as a low-count segment and excluded from matching.
  4. Mean-pool every valid segment's face embeddings into one aggregate vector, then L2-normalize it for cosine similarity.
  5. For every camera pair in the scene, build a similarity matrix. Its shape may be 2x2, 2x1, 1x2, or 1x1.
  6. Select the highest-scoring matrix cell as the shared-person match. For 1x1, accept only when the score is at least 0.70.
  7. Assign the matched segment in both clips to the expected common person id.
  8. If one valid segment is mapped and exactly one other valid selected segment remains in the same view, infer it as the other visible person.
  9. If evidence conflicts, leave that segment unresolved and record the conflict in JSON.
  10. If a chunk has any conflict, try the next chunk for the same scene. Continue until a chunk has zero conflicts, or all chunks are exhausted.
  11. If all chunks conflict, keep the best-ranked attempt and record every chunk attempt in chunk_attempts.
Conflict-driven chunk fallback evaluates chunks without writing visuals, then writes crops only for the selected chunk.
Smoke-test example for person 1 view against person 2 view in day_1__con_1__part1.

Representative Frame and Crop

Once a segment is mapped, the script chooses the most representative face frame for visualization and downstream use. It compares every per-frame embedding for the segment to the segment's aggregate embedding and selects the row with the highest cosine similarity that still has a refined mask and an image frame available.

Representative crop selection uses the already-computed face embeddings and refined masks.

Important Edge Cases

  • Missing third view: scenes with two camera views still map the single common person between those two cameras.
  • Only one valid segment on one side: matrices become 2x1 or 1x2 and still use the best cell.
  • Only one valid segment on both sides: 1x1 matches are accepted only when cosine similarity is at least 0.70.
  • Top counted mask lacks embedding: the segment is recorded in missing_embedding_segment_ids and is not replaced by another segment.
  • Too few face embeddings: a selected segment with fewer than 10 embeddings is recorded in low_embedding_count_segment_ids and excluded.
  • Conflicting evidence: conflicting segment assignments are nulled and listed under conflicts.
