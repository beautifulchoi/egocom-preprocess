EgoCom Window Manifest Builder

This step merges 1-minute EgoCom chunk outputs into shorter multimodal samples and writes pairwise manifest rows. Each row contains source and target audio windows, target geometry observed from the source camera, target CLIP visual features, target T5 text features, and target final person-mask windows aligned to the same 5 FPS frame grid. When requested, it also writes source and target original-video clips for the same window interval.

Flow

Target Mask Matching

The final mask source is {data_root}/{chunk_root}/{split}/final_mask, produced by Step 09. For each manifest row, the builder uses the source camera video and the target person id: {scene}/chunk_XXXX/{src_video_name}_chunk_XXXX/person_{tgt_person_id}. This matches the target audio/person identity while preserving the same source-camera viewpoint used by target geometry and masked visual features.

Output mask windows are written under final_mask/{scene}/{src_video_name}/target_person_{tgt_person_id}/{sidecar_name}/. Each directory contains window-local mask JPGs plus summary.json with source mask paths, source chunk indices, and frame provenance. If a source chunk has no Step 09 folder for the target person, the window writer emits black masks at the corresponding source-frame size and records those frames as black fallbacks. Manifest rows store tgt_mask_path, tgt_mask_num_frames, tgt_mask_valid_ratio, and aligned mask start/end timestamps.

Chunk Aggregation

The builder uses the frame folders under {data_root}/{chunk_root}/{split}/frame/{video}_chunk_* to recover the real chunk timeline. Consecutive chunks are placed back-to-back using their actual frame counts, so short tail chunks remain aligned with the original audio instead of being forced onto fixed 60-second boundaries.

For example, a sequence with frame counts 300, 300, 300, 202, 202 at 5 FPS is aggregated as frame intervals [0,300), [300,600), [600,900), [900,1102), and [1102,1304). The fifth chunk therefore starts around 220.4 seconds, not 240.0 seconds.

If frame folders are unavailable, the code falls back to the nominal --chunk-sec spacing. Ignored and conflicted source-chunk checks use the same recovered intervals, so their filtering matches the corrected multimodal alignment.

Filtering

Source chunk filtering uses /home/prj/data/egocom_holdout/ignore_video_chunks/{split}.txt. A row is dropped when the source window overlaps any listed chunk. This removes manually rejected mirror-conflict regions without removing the full original video.

Mapping-conflicted chunks are also excluded before loading feature streams. The builder reads person_face_mapping/*/summary.json, marks chunks with conflict segments or fully conflicted fallback status, skips those chunk files, and drops windows whose source interval overlaps them.

Fully absent target visual windows are also dropped. A window is fully absent when its target CLIP frame_statuses contain no masked frame. The drop counter is fully_absent_target_visual.

Test windows additionally require at least 25 percent valid target geometry. With the default 4-second test crop this means at least 5 of 20 geometry frames must be valid. The drop counter is low_geometry_valid_ratio.

All splits now drop the final tail when it is shorter than the configured window length. Train and validation keep only complete 6-second windows, and test keeps only complete 4-second windows.

The 10-second outputs follow the same tail rule: final segments shorter than 10 seconds are dropped. No 10-second output pads the final partial window.

Raw text rows can still be null, but the T5 features were encoded from The target person is not visible. for those frames.

Optional small test manifests can be restricted with --audio-stem-allowlist. This is an exact source/target original-audio filter: both people in a pair must have stems in the allowlist. The option requires at least one stem, is separate from duration filtering, and avoids pulling in other videos that happen to be shorter than a threshold.

10-Second Manifests

The 10-second full train output uses 5-second overlap, so starts advance by 25 frames at 5 FPS. The 10-second full validation and test outputs are non-overlap, so starts advance by 50 frames.

Strict alignment is identical to the 6-second and 4-second builds. For each row, audio covers [clip_start_ms, clip_end_ms), and geometry, CLIP, and T5 all slice the same [aligned_start_frame, aligned_end_frame) interval. For a 10-second row, that interval always contains 50 frames.

The test command uses --test-min-geometry-valid-ratio 0.25 by default. Set it to a negative value only when deliberately disabling that filter.

These commands write new multimodal manifests and summaries without replacing existing manifest.jsonl files. Existing audio, geometry, and CLIP sidecars are reused when present; the new T5 sidecars and multimodal manifest can be regenerated with --overwrite.
