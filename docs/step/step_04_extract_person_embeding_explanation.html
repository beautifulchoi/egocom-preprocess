Person Face Embedding Extraction

This page explains how /home/prj/egocom_preprocess/src/step_04_extract_person_embeding.py extracts face identity embeddings from refined person masks. The script uses InsightFace only to find face boxes, then uses StyleID to create the final embedding vectors.

Goal

Each refined mask file contains person segment ids over video frames. The goal is to produce a face-style embedding for each segment id when the person's face is visible. These embeddings can be used later as compact identity or appearance features for the visible person track.

The script does not use InsightFace recognition embeddings. It only uses InsightFace face detection. The embedding is generated by StyleID, implemented as a Hugging Face CLIPModel.

Inputs and Outputs

Item Default path or value Purpose
Refined mask {split}/refined_mask/{video_name}/mask.pt Stores frame index to segment id to binary mask.
Frames {split}/frame/{video_name}/*.jpg Original RGB frames that are masked and cropped before face detection.
Embedding output {split}/person_embeding/{video_name}/embeding.pt Dictionary from valid segment id to tensor shaped [num_embeddings, 768].
Summary output {split}/person_embeding/{video_name}/summary.json Human-readable processing statistics, validity flags, devices, and model names.
A segment id is saved in embeding.pt only if at least one valid face embedding was extracted. If a segment never has a detected face, it is omitted from embeding.pt and listed in summary.json as an invalid segment.

Pipeline

1. Load masks Read mask.pt safely with torch.load(..., weights_only=True) and normalize masks into boolean NumPy arrays.
2. Mask frame For each frame and segment id, resize the mask if needed and zero out pixels outside the person mask.
3. Detect face Run InsightFace on the masked person crop. If multiple faces are found, keep the one with the best overlap with the person mask.
4. Embed crop Crop the selected face, process it with StyleID image preprocessing, and run model.get_image_features.
5. Save result Concatenate all valid embeddings per segment id and write the tensor dictionary plus JSON summary.

What Gets Cropped

There are two different crops in the script. The first crop is used only to make face detection easier. The second crop is the actual image sent to StyleID for embedding extraction.

Person mask and mask bbox person_padding detector crop InsightFace face box face_padding StyleID crop

person_padding

This expands the person-mask bounding box before face detection. It helps when the mask is tight around the body or clips the edge of the face. Pixels outside the mask are still set to black, so the detector mainly sees the current person.

This padding does not directly decide the final StyleID image. It only changes where InsightFace searches for a face.

face_padding

This expands the selected face detection box after detection. The resulting padded face crop is the image passed to StyleID. Increasing this value includes more hair, jaw, and nearby context. Decreasing it makes the crop tighter around the detected face.

Detailed Steps

Mask loading

The mask file is expected to be a dictionary where each frame index maps to a dictionary of segment ids. Each segment id maps to a 2D binary mask. Empty masks and malformed masks are ignored. The script preserves the segment ids from the mask file.

Person crop and masked image

For each mask instance, the script computes the person bounding box and expands it by --person_padding. The frame is cropped to this region, and every pixel outside the person mask is set to black. Face detection is run on this masked crop instead of the full frame, so the detector is biased toward the current segment id.

Example: if the mask bbox is x=100..220, y=80..300, the larger dimension is 220 pixels. With --person_padding 0.08, the crop is expanded by about 18 pixels on each side, then clipped to the image boundary.

Face detection

The default InsightFace model pack is antelopev2. The script loads only the detection module, currently scrfd_10g_bnkps.onnx. Landmark, age, gender, and InsightFace recognition modules are ignored because they are not needed for this task.

If more than one face is detected in the crop, the script selects the face with the largest overlap against the person mask. The detector confidence score is used as a tie breaker. Detections below --min_face_score are ignored.

The face box returned by InsightFace is local to the padded person crop. The script converts it back into full-frame coordinates before making the final StyleID crop. This avoids embedding a crop from the masked black-background image. StyleID receives a crop from the original frame.

StyleID embedding

The face crop is converted to RGB PIL format and embedded with: 

model = CLIPModel.from_pretrained("kwanY/styleid")
processor = CLIPImageProcessor.from_pretrained("kwanY/styleid")
emb = model.get_image_features(**inputs)
emb = emb / emb.norm(dim=-1, keepdim=True)

CLIPImageProcessor is used because the script only needs image preprocessing for get_image_features. The output embedding dimension is recorded in summary.json; with the current StyleID model it is 768.

Each successful face crop produces one normalized row vector. For a segment id, all row vectors are stacked together in frame order. The final tensor shape is therefore [number_of_successful_face_frames, 768].

No-face segments

A segment may have masks but no detected face. This can happen when the head is outside the frame, the face is turned away, the mask covers only the body, or the face is too small or occluded. These segments are not saved as zero vectors. They are omitted from embeding.pt and listed in invalid_segment_ids in the summary.

Model and Device Behavior

Component Model Device behavior
Face detector InsightFace antelopev2, detection module only Uses ONNXRuntime. If --device cuda or --device auto selects CUDA, the script requires CUDAExecutionProvider. If it is missing, the script fails instead of silently using CPU.
Embedding model kwanY/styleid Uses PyTorch. The model is moved to the selected device and the saved summary records styleid_device.
The summary records insightface_detector_providers and styleid_device, so each output folder shows whether detector and embedding models actually used GPU.

Output Format

embeding.pt

This file is saved with torch.save. It contains only valid segment ids: 

{
  0: tensor with shape [num_valid_faces_for_segment_0, 768],
  1: tensor with shape [num_valid_faces_for_segment_1, 768]
}

The number of rows can be different for each segment because faces are visible in different numbers of frames.

Concrete Example

A full-frame run on vid_001__day_1__con_1__person_1_part1_chunk_0001 produced this output: 

embedding keys: [0, 1]
segment 0 shape: [218, 768]
segment 1 shape: [243, 768]
invalid_segment_ids: [2]
num_omitted_invalid_segments: 1

This means segment ids 0 and 1 had visible detected faces in many frames, so their embeddings were saved. Segment id 2 had no valid face embedding, so it was not saved in embeding.pt and was recorded only in the JSON summary.

The corresponding summary also records: 

insightface_detector_providers: ["CUDAExecutionProvider", "CPUExecutionProvider"]
styleid_device: "cuda:0"

summary.json

Important fields include:

Field Meaning
valid_segment_ids Segment ids saved in embeding.pt.
invalid_segment_ids Segment ids with no valid face embedding.
num_omitted_invalid_segments How many segment ids were omitted from embeding.pt.
per_segment Per-id counts for mask frames, processed frames, detections, no-face frames, and embedding validity.
insightface_detector_providers Actual ONNXRuntime providers for InsightFace detection.
styleid_device Actual PyTorch device for the StyleID model.

Common Commands

Run on one explicit mask file and write to person_face_emb:

python /home/prj/egocom_preprocess/src/step_04_extract_person_embeding.py \
  --mask_path /home/prj/data/egocom_holdout/1min/train/refined_mask/vid_001__day_1__con_1__person_1_part1_chunk_0001/mask.pt \
  --output_root /home/prj/data/egocom_holdout/1min/train/person_face_emb \
  --overwrite

Run on one named video using the default dataset layout:

python /home/prj/egocom_preprocess/src/step_04_extract_person_embeding.py \
  --split train \
  --video vid_001__day_1__con_1__person_1_part1_chunk_0001 \
  --overwrite

Run a quick smoke test on only the first 30 frames:

python /home/prj/egocom_preprocess/src/step_04_extract_person_embeding.py \
  --mask_path /path/to/mask.pt \
  --frame_dir /path/to/frame_dir \
  --output_dir /tmp/person_face_emb_smoke \
  --max_frames 30 \
  --overwrite

Useful Parameters

Parameter Default Effect
--sample_every 1 Process every Nth frame. Use a larger value for faster approximate extraction.
--max_frames not set Stop after this many frames. Useful for smoke tests.
--det_size 640 InsightFace detector input size. Larger can help small faces but costs more memory and time.
--min_face_score 0.3 Minimum detector confidence required before a face is embedded.
--person_padding 0.08 Extra area around the person mask box before running face detection.
--face_padding 0.25 Extra area around the selected face before StyleID embedding.
--device auto Selects CUDA when PyTorch CUDA is available, otherwise CPU.
If --device auto selects CUDA but ONNXRuntime does not have CUDAExecutionProvider, the script raises an error. Install a compatible onnxruntime-gpu package or run with --device cpu.
