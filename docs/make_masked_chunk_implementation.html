Final Mask Overlay Chunk Video Implementation

This document explains vis_maker/make_final_mask_overlay_videos.py, the debugging utility that turns saved final_mask JPGs into view-level overlay videos. The videos are intended for quickly checking whether each extracted person mask follows the correct person while keeping the original scene context visible.

Purpose

Step 9 saves one binary mask image per target person and per source frame. The overlay video maker validates those files visually by compositing all target-person masks for one ego-view clip onto the original RGB frames. Each view inside a chunk becomes one MP4, and the two target people in that view are shown together with different colors.

Input and Output Layout

ArtifactPathUse

Final masks {data_root}/{split}/final_mask/{scene}/chunk_XXXX/{view_clip}/person_{id}/frame_XXXXXX.jpg Binary masks for each target person in the view.

Summary JSON {data_root}/{split}/final_mask_overlay_video/summary.json Records processed videos, paths, codec, frame counts, and mask counts.

Dataset Traversal

The script discovers work from the saved final_mask tree. With --split all_existing, it processes every split containing both final_mask and frame. It then walks scene directories, chunk directories, view clip directories, and finally all person_* mask directories inside the view.

Job Construction

Each discovered view clip becomes an OverlayJob with the split name, scene key, chunk name and index, view clip name, frame directory, mask directory, output path, and sorted person_* directories. Sorting by numeric person id keeps colors and legend order stable across runs.

  • --scene_key restricts processing to one scene.
  • --chunk restricts processing to one numeric chunk id.
  • --video restricts processing to one exact view clip name.
  • --limit stops after a fixed number of view videos.

Per-Frame Overlay Procedure

For every source frame, the script loads the frame image and all masks with the same filename from the view's person_* directories. Missing or unreadable mask files are treated as empty masks and counted in the summary. Mask images are thresholded at > 127 and resized with nearest-neighbor interpolation if needed.

Compositing Logic

RegionImplementationReason
Background output = frame * background_alpha, default 0.5 Background remains visible but dimmed, so foreground masks are easier to judge.
Foreground frame + color * foreground_alpha, clipped to 255 Person pixels keep full original brightness while receiving a strong color highlight.
Overlapping masks Person colors are accumulated and averaged at overlapped pixels. No person's mask is dropped when two masks overlap.
Mask boundary cv2.findContours and cv2.drawContours(..., thickness=2) Boundaries stay visible even when the color fill blends with the original image.
Legend A small top-left legend lists person_{id} with its color swatch. The debug video can be inspected without looking up the person-color mapping.

Color Assignment

The script uses stable BGR colors keyed by numeric person id. Person ids 1 through 6 have fixed colors. Larger ids use a fallback palette indexed by person id. This makes repeated renders visually consistent.

Video Encoding

Frames are first written through OpenCV using an intermediate MP4 codec controlled by --codec, default mp4v. By default, if ffmpeg is available, the temporary MP4 is transcoded to H.264/yuv420p with libx264, -pix_fmt yuv420p, and -movflags +faststart. This makes the output more compatible with VSCode and browser video previewers. Use --no_h264 to keep the raw OpenCV MP4 instead.

Procedure Summary

  1. Discover splits with both final_mask and frame.
  2. Collect one job per {scene}/chunk_XXXX/{view_clip}.
  3. For each frame, load the original image and same-named mask images from every person_* directory.
  4. Threshold masks, resize if needed, and compute a union foreground region.
  5. Dim non-person background to 50% brightness.
  6. Render person foreground at full image brightness with person-specific color highlights, contours, and legend.
  7. Write frames to MP4 and transcode to H.264/yuv420p when ffmpeg is available.
  8. Write summary.json with output paths, codec status, person ids, frame counts, and mask counts.

Summary Fields

Each video entry in summary.json records status, split, scene, chunk, view clip, source directories, output path, codec, h264_status, FPS, width, height, person labels, number of source frames, and counters such as written_frames, nonempty_masks, empty_masks, missing_or_unreadable_masks, and unreadable_frames.

The generated videos are debug artifacts. They are saved under the data tree by default, not under the repository, so full-dataset renders do not bloat the source checkout.
